## Diagram relationship audit

| Diagram              | Meaning of every connector or ordering                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| System boundary      | Application ↔ API is client-initiated submission/query and response. Worker ↔ API is client-initiated wait/report and response. Both API operations and server maintenance read/write the same SQL store. The worker is outside the server boundary.                                                                                                                                                                                                        |
| Successful execution | New submission precedes acquisition; local business execution follows the returned assignment; completion is then reported. This is a representative successful path with work available, not an assertion of exactly three network requests in every SDK run. Polling, repeated waits, and report delivery retries can add requests.                                                                                                                       |
| Selection            | Application/type and due-state eligibility precede priority sorting. The tie sequence is eligible time, creation time, ID. The selected job and new attempt share a transaction; no job-to-job execution-order guarantee is drawn. Priority bars indicate rank, not throughput or probability.                                                                                                                                                              |
| Lifecycle            | Queued → Processing occurs on acquisition. Processing branches to Completed on accepted completion, Retrying on retryable failure/timeout with remaining budget, DeadLettered on permanent failure/exhaustion, or Cancelled on accepted cancellation. Retrying → Processing abbreviates the internal QueueRetry then StartProcessing sequence once due and acquired. Queued/Retrying cancellation and construction-only Pending are covered by the caption. |
| Time and recovery    | Acquired → deadline represents the fixed execution window. Lease expiry is deadline plus grace. The 5 → 10 → 20 second sequence is the default retry-delay progression, not a continuous execution timeline or exact time-to-next-execution.                                                                                                                                                                                                                |
| Repeated requests    | Submission arrows describe existing-job versus conflict responses. Report arrows describe duplicate acknowledgment versus conflicting-result rejection. The separately bordered business-effect area is application-owned; there is no server-to-receiver transaction.                                                                                                                                                                                      |
| Persistence          | One job → many attempts is the mapped foreign-key relationship, not a network request or an assertion that every queued job already has an attempt. Displayed fields are real mapped properties; the view is an intentionally partial schema.                                                                                                                                                                                                               |

- No unavailable illustrations were substituted with fictional screenshots. Every visual is local HTML/CSS/SVG.
- Browser verification uses Chromium and the production artifact served locally under `/Portfolio/`; it is not a new live deployment or a cross-browser certification.
